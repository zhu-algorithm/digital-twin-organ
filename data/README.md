# Data contract

Raw patient data is deliberately not committed. A cell table must contain one row per cell, `patient_id`, `cell_type`, and any available signature-gene columns. Labels must contain one row per patient with `patient_id,response`, where response is binary 0/1 and is defined before analysis (for example RECIST CR/PR vs SD/PD).

Optional paired scRNA/TCR input columns are `clonotype_id` and `tissue`. When present, the pipeline adds clone richness, Simpson concentration, normalized entropy, top-clone fraction and the fraction of TDLN clonotypes also observed in tumour. `tissue` values are matched case-insensitively on `tdln`/`lymph` and `tumour`/`tumor`; projects should harmonize these labels before analysis.

If a recognized temporal column (`sampling_day`, `timepoint`, `visit`, or `collection_timepoint`) is present, `featurize` and `qc` fail until `--time-column` and explicit comma-separated `--baseline-values` are supplied. Every patient must retain at least one selected cell. This prevents post-treatment cells from entering a baseline response model through silent pooling. For example, use `--time-column timepoint --baseline-values baseline,pre_treatment` or numeric values such as `--time-column sampling_day --baseline-values -7,0`.

When `tissue` is present, expression signatures and cell fractions use only rows matching the default `tdln|lymph` pattern. TCR diversity and TDLN–tumour clone sharing continue to use all selected paired tissues. Override the expression compartment with `--feature-tissue-pattern`, or pass `all` only when cross-tissue aggregation is explicitly intended. Each patient must have at least one cell in the selected expression compartment.

An optional patient-level `tumour_antigen_proxy` may be supplied to `augment-twin` after featurization when it comes from a documented assay such as neoantigen burden or lymph antigen measurement. It must be a finite non-negative relative scale. The pipeline does not derive this quantity from interferon-expression signatures; when absent it preserves the population default. Hybrid output includes systemic endpoints plus treated/control efferent-effector and treated paracortical-Tpex spatial endpoints. These simulated columns are model-derived covariates, not measured biomarkers.

Spatial initialization uses a separate spot table with `spot_id,patient_id,zone,antigen,mature_dc,tpex,effector` and an optional area or cell-count weight. `zone` must be one of `afferent_lymph`, `subcapsular_sinus`, `paracortex`, `follicle`, `medulla`, or `efferent_lymph`. The four abundance columns must be finite and non-negative and should come from a documented segmentation/deconvolution method. Recognized temporal columns have the same explicit `--time-column`/`--baseline-values` contract as cells, every patient must retain baseline spots, and those settings are stored in the spatial audit. `spatial-featurize` sums the selected weighted spot abundances into auditable patient-zone-species states; it does not infer zones from raw coordinates or convert arbitrary expression scores into absolute cell counts.

For mechanism–ML fusion, pass that output to `augment-twin --spatial-initial-zones`. Its patient identifiers must match the single-cell feature table exactly. No inner join or population-default fallback is performed when a spatial table is requested, so incomplete multimodal linkage fails rather than silently changing the analysis cohort.

Longitudinal spatial calibration uses `day,species,zone,amount,sd`, with one unique row per time/species/zone coordinate. Amounts must be finite and non-negative and standard deviations strictly positive. Species and zones use the same controlled vocabulary as spatial initialization. Observation units must match the initial-state amounts; the calibration command does not infer conversions between expression, density, imaging intensity and cell counts.

Fitted parameter files are complete JSON serializations of `TwinParameters` or `SpatialParameters`. Downstream commands reject missing, extra, non-finite or non-positive fields and write an adjacent `.parameters.json` sidecar containing the exact SHA-256 used. Retain that sidecar with every simulated or hybrid dataset so model inputs can be traced back to a specific calibrated parameter bundle.

The repository's existing CELLxGENE-derived organ files are useful provenance/context but do **not** contain a verified paired TDLN cohort with anti-PD-1 outcomes. They are therefore not silently reused as supervised labels.

Every imported cohort should ship a JSON provenance manifest with `cohort_id`, `source`, `license`, `modalities`, `outcome_definition`, and a list of files containing relative `path`, semantic `role`, and SHA-256. `tdln-pd1 qc` verifies the hashes and fails closed on missing files, altered content, ambiguous timepoints, missing/duplicate patients, invalid response labels or a single-class matched cohort. Its report records raw and selected cell counts, the exact temporal selection, response balance, signature coverage, paired TDLN–tumour availability and clonotype assignment.
